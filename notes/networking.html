1Do you need this?

Video: slide 1

Yes, though not with the depth of a network engineer or a systems administrator. Networking is what bridges code that runs on your laptop and an application running in production, and it shows up in three places:

  • Frontend to backend. Full stack is client and server by definition, so you live in HTTP: methods, headers, status codes, JSON. You will meet CORS, and you will need to know when a request should become a WebSocket.
  • Containers and cloud. Applications run in containers now, so you need to know how containers reach each other, what a port mapping means, 0.0.0.0 against 127.0.0.1, and public against private subnets.
  • Security and performance. You own the data in transit and the user's wait: how TLS and certificates work, what a reverse proxy or a load balancer does, and why round trips matter more than bandwidth.

2One request, five steps

Video: slide 2

  1. Find the address: DNS. A name like example.com means nothing to a router, so it has to become a number.
  2. Open a connection: TCP. A three-message handshake, so both ends agree they are talking. One round trip.
  3. Agree on secrecy: TLS. Prove the server is who it says it is, and agree encryption keys. At least one more round trip.
  4. Ask and answer: HTTP. Send the request as text, and wait for the response.
  5. Keep it or close it. Reuse the connection for the next request, or pay for steps 2 and 3 all over again.

Three of the five are waiting for a reply from somewhere else. That is where the time goes (section 7).

3The layers

Those steps live in layers. Each layer does one job and trusts the one below it to do the rest.

LayerIts jobWhere you meet it in Python
HTTPwhat you are asking forrequests, http.client, Flask
TLSprivacy, and proof of identityssl, inside requests where you never see it
TCP / UDPa reliable ordered stream, or single packets with no promisessocket
IPgets a packet to the right machinesocket, the bottom of it all

A single requests.get on an https address uses all four layers, which is exactly why it can fail in four different ways. A ConnectionError, an SSLError and a 500 status are three different layers telling you three different things. Reading which one you got is the first step of every network debugging session.

4Addresses and ports

The address picks the machine. The port picks the program on that machine.

PortWho listens there
22SSH
53DNS
80 / 443HTTP / HTTPS
5000Flask's development server
8000Django, Uvicorn, Gunicorn
5432 / 3306 / 6379PostgreSQL / MySQL / Redis

A connection is actually four numbers: your address and port, and theirs. That is how one server holds thousands of connections on the same port 443 at the same time: every one has a different pair at your end.

Some addresses are private: 10.x.x.x, 172.16 to 172.31, and 192.168.x.x. Your laptop almost certainly has one. Your home router swaps it for a single public address on the way out, so a server on the internet never sees the private one.

"Address already in use" almost always means something is already listening on that port. Usually it is the dev server you started an hour ago and forgot.

5DNS: names into numbers

Video: slide 3

The script builds a DNS question by hand and sends it as one UDP packet to 1.1.1.1, Cloudflare's public resolver. This is the whole question, 29 bytes:

00 01 01 00 00 01 00 00 00 00 00 00   # 12: header: an id, "please recurse", one question
07 65 78 61 6d 70 6c 65 03 63 6f 6d 00  # 13: 7 · example · 3 · com · end
00 01 00 01                              # 4: type A (an IPv4 address), class IN

61 bytes came back: two addresses for example.com, each with a TTL (time to live) of 291 seconds, which is how long anyone may cache the answer. The round trip to the resolver took 4.0 ms; the operating system's own cache answered in 0.5 ms.

The TTL is why a DNS change "takes time to propagate". It does not propagate: everybody holding the old answer keeps it until its TTL runs out. Most DNS questions never leave your machine at all.

6TCP or UDP

Two ways to send data, making opposite trades.

  • TCP is a phone call. Connect first with a handshake, then an ordered, reliable stream: lost packets are resent, nothing arrives out of order. HTTP, HTTPS, SSH, every database connection and WebSockets run on TCP.
  • UDP is a postcard. No connection, no promise: one packet out, maybe one back, which is all a DNS question needs. Voice and video calls use it, games use it, and so does QUIC, which carries HTTP/3.

TCP's reliability costs a round trip before the first byte; UDP's speed costs the guarantees. HTTP/3 runs over UDP so that QUIC can set up the connection and the encryption together, in a single round trip.

The page is 1,067 bytes. Almost none of the 197 ms was downloading; it was waiting for replies. A faster connection would barely change this number. Fewer round trips would change it a lot (section 10). The 18.9 ms at the top of the DNS range is one lookup that missed the cache.

8TLS: privacy and proof

A certificate proves that this server holds the private key for this name, vouched for by a certificate authority your operating system already trusts. You get one by proving to an authority that you control the domain; Let's Encrypt does it free and automatically. TLS 1.3 completes its handshake in one round trip, where TLS 1.2 needed two.

verify=False does not fix a certificate error. It switches off the half of TLS that tells you who you are talking to.

9HTTP is text

The request the script sent, exactly: 82 bytes. You could type it by hand.

GET / HTTP/1.1
Host: example.com
User-Agent: net_bench.py
Connection: close

And the response: 1,067 bytes, 342 of headers and 725 of page.

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Connection: close
Server: cloudflare

Two things to know cold:

  • Methods. GET reads, POST creates, PUT replaces, DELETE removes. GET must never change anything: browsers, caches and crawlers repeat GETs whenever they like.
  • Status codes, by the first digit. 2xx it worked; 3xx look somewhere else; 4xx the request was wrong (the client's side); 5xx the server failed (our side).

An API that returns JSON says so in its Content-Type header, but the body is still text. Every Python web framework is building and parsing exactly these lines.

10Keep the connection

Video: slide 6

Ten requestsPer request
Ten new connections1,304 ms130.4 ms
One kept-alive connection432 ms43.2 ms

Three times faster, without changing the requests. Each new connection pays for TCP and TLS again; a reused one pays once.

# ten requests, ten connections
for url in urls:
    r = requests.get(url)

# ten requests, one connection
with requests.Session() as s:
    for url in urls:
        r = s.get(url)

You already rely on this: requests.Session() keeps connections open, a database connection pool does the same for your queries (the GIL talk counts how many pools your workers hold), and browsers do it for every page.

11Distance is milliseconds

Video: slide 7

Light in fiber covers about 100 km of distance for every millisecond of round trip, so a round trip puts an upper bound on how far away the other end can be.

One TCP round trip toMedianSo it is at most
this laptop (127.0.0.1)0.28 msno distance: the operating system's own time
nearest Cloudflare server (1.1.1.1)1.65 ms~165 km away
example.com, port 44323.75 ms~2,375 km away

The middle row is what a CDN is: copies of the content, placed near the people who ask for it. And a whole HTTP request to a server on this laptop took 2.10 ms; the real page in section 7 took 94 times as long. Everything feels instant in development because nothing is far away, and that is where the ORMs talk's N+1 problem hides: a hundred queries on a laptop is nothing, a hundred round trips to a real database is not.

Why is example.com so much slower than 1.1.1.1, when both are Cloudflare? From this laptop, a TCP connect to example.com's address took about 2 ms on port 80 and about 24 ms on port 443, so something on this network path treats port 443 to that address differently. It is visible in the measurements and not explainable from here, which is why these are upper bounds, not distances.

12Always set a timeout

Video: slide 8

Connecting to an address that never answersGave up after
timeout=22.0 s
no timeout (Python's default)21.0 s

socket.getdefaulttimeout() is None, and None means "as long as the system will": Windows gave up after 21 seconds, and Linux, by default, waits about two minutes. requests has no default timeout either; pass one, as a pair:

requests.get(url, timeout=(3, 10))   # 3 s to connect, 10 s to read

One slow upstream service without a timeout ties up every worker that calls it. Then there are no workers left, and the whole site is down because of somebody else's outage. A timeout turns "the site is frozen" into "one call failed". requests' own documentation says nearly all production code should pass one.

13CORS

Video: slide 9

An origin is three things: the scheme, the host and the port. So http://localhost:3000 and http://localhost:5000 are different origins, which is your React frontend and your Flask API on one laptop, on day one.

The browser will not let a page read a response from another origin unless that server says it may. curl and Python never hit CORS: it is a browser rule, and it protects the browser's user, not your server. Your API received the request either way.

# the API answers, naming who may read it
Access-Control-Allow-Origin: http://localhost:3000
  • The preflight. For a JSON POST the browser first asks permission with a separate OPTIONS request, which is why DevTools shows two requests.
  • With cookies, name the origin exactly: a wildcard * is refused once credentials are involved.
  • In Flask, the flask-cors extension sets these headers in two lines.

Fix CORS on the server that owns the data. A frontend cannot grant itself permission.

14WebSockets and server-sent events

HTTP is ask, answer, done. Some features need the server to speak first: a chat message arriving, a live dashboard, a collaborator's cursor.

A WebSocket starts as an ordinary HTTP request with an Upgrade header. The server answers 101 Switching Protocols, and from then on the same TCP connection carries messages in both directions for as long as both ends want.

UseFor
HTTPpages, API calls, forms
WebSocketschat, live collaboration, games
Server-sent eventswhen only the server needs to talk: one way, plain HTTP, so it passes every proxy that HTTP does

KuantorFlow streams its AI companion's replies with server-sent events. One Python catch: WSGI cannot hold a connection open, so WebSockets need ASGI (the Async talk).

15localhost or 0.0.0.0

Video: slide 10

Server bound toReached via 127.0.0.1Via the laptop's own address
127.0.0.1connectedfailed
0.0.0.0connectedconnected
  • 127.0.0.1 means this machine only. Flask's app.run(), Gunicorn and Uvicorn all default to it. Inside a container, 127.0.0.1 means the container itself, so traffic arriving through the published port has nothing listening for it: the first Docker deploy starts, the logs look fine, and it cannot be reached.
  • 0.0.0.0 means every network the machine is on. That is what a container needs: gunicorn -b 0.0.0.0:8000.

On your laptop, 0.0.0.0 shows your dev server to the whole café Wi-Fi. And Flask's debugger is a Python shell in the browser: bound to 0.0.0.0, that shell is open to everyone on the network.

16Docker networking

services:
  web:
    build: .
    ports:
      - "8000:8000"          # host:container
    environment:
      DATABASE_URL: postgresql://app:${DB_PASSWORD}@db:5432/app
  db:
    image: postgres:16     # no ports: nobody outside should reach it
  • Inside a container, localhost is the container. Not your laptop, and not the database container next to it.
  • Containers find each other by name. On a Compose network, Docker runs its own DNS that turns the service name into an address: the host in DATABASE_URL is the word db.
  • 8000:8000 is host:container. The left number is the port on your machine, the right one inside the container, and they do not have to match. Publish only what must be reached.

So when a container says "connection refused to localhost:5432", it is looking for Postgres inside its own container. Change one word to db.

17Public and private subnets

In the cloud, the question is not only whether a server works, but who can reach it at all. The usual shape has three tiers:

  1. Public subnet: only the load balancer, with a public address. Your domain's DNS points at it; it is the single front door.
  2. Private subnet, the app: app servers with private addresses only. The load balancer reaches their port 8000; the internet cannot reach them at all.
  3. Private subnet, the data: the database, no public address, and firewall rules that admit only the app servers, on 5432.

Each tier accepts traffic only from the tier in front of it: the Compose file's idea again, publish only what must be reached. AWS, Google Cloud and DigitalOcean name the pieces differently; the shape is the same.

18Reverse proxies and load balancers

In front of the app servers sits a reverse proxy, such as Nginx or Traefik, doing four jobs Python should not:

  • It ends HTTPS: it holds the certificate, and the hop to your app is plain HTTP inside the private network.
  • It serves static files, quickly, so a Python worker is never spent on a logo.
  • It routes by hostname or path: /api to one service, everything else to another.
  • It spreads the load across Gunicorn workers and machines, and stops sending to one that has failed.

The catch: your app now sees the proxy, not the user, and request.remote_addr becomes the proxy's address. Werkzeug's ProxyFix reads the X-Forwarded-For header to recover the real one, but configure it with the number of proxies you actually have: a client can send that header too, and trusting more hops than exist lets it choose its own address.

20Run it yourself

Every number in the video and on this page comes from net_bench.py: Python's standard library only, nothing to install. Run python net_bench.py; it takes about a minute and talks to example.com and 1.1.1.1. The figures are medians of eight runs from one laptop on 2 October 2026; your connection will give different numbers, which is the point.

Two choices in it come from traps found while building it. It reports medians, because during testing one slow packet in eight tripled a mean. And on Windows a socket with a timeout waits via the system timer, whose tick is about 15.6 ms, so the script times its fast local requests without one (a 0.9 ms loopback request had measured 8.8 ms).

# -*- coding: utf-8 -*-
"""Take one HTTPS request apart, on this machine, with nothing but the stdlib.

Every number the Networking talk quotes comes from this script. Each
experiment runs RUNS times and reports the median and the range, because one
network measurement on its own is an anecdote.

    python net_bench.py

  1. Anatomy   — one HTTPS request to example.com, phase by phase.
  2. DNS       — a hand-built 29-byte query to a public resolver, over UDP.
  3. HTTP      — the request and the response, as the bytes they really are.
  4. Reuse     — ten requests on ten connections vs ten on one connection.
  5. Distance  — one TCP round trip to localhost, a nearby CDN server and example.com.
  6. Timeouts  — what a connect to nowhere does with, and without, a timeout.
  7. Binding   — a server on 127.0.0.1 vs one on 0.0.0.0, reached two ways.

example.com is reserved by IANA for documentation and examples; 1.1.1.1 is
Cloudflare's public DNS resolver. Nothing here sends anything about you.
"""
import http.client
import http.server
import socket
import ssl
import statistics as st
import struct
import threading
import time

HOST = "example.com"
RESOLVER = ("1.1.1.1", 53)
RUNS = 8
MS = 1000.0


def ms(seconds):
    return seconds * MS


def summary(values, unit="ms", fmt="{:.1f}"):
    return (f"{fmt.format(st.median(values))} {unit}  "
            f"(range {fmt.format(min(values))}-{fmt.format(max(values))})")


# ═══════════════════════════════════════════════════ 1. anatomy of a request
REQUEST = (f"GET / HTTP/1.1\r\nHost: {HOST}\r\n"
           f"User-Agent: net_bench.py\r\nConnection: close\r\n\r\n").encode()


def one_request():
    """Time each phase of one HTTPS request separately."""
    t = {}
    t0 = time.perf_counter()
    ip = socket.getaddrinfo(HOST, 443, socket.AF_INET, socket.SOCK_STREAM)[0][4][0]
    t1 = time.perf_counter()
    raw = socket.create_connection((ip, 443), timeout=10)
    t2 = time.perf_counter()
    tls = ssl.create_default_context().wrap_socket(raw, server_hostname=HOST)
    t3 = time.perf_counter()
    tls.sendall(REQUEST)
    first = tls.recv(65536)
    t4 = time.perf_counter()
    body = first
    while chunk := tls.recv(65536):
        body += chunk
    t5 = time.perf_counter()
    info = {"ip": ip, "version": tls.version(), "cipher": tls.cipher()[0],
            "cert": tls.getpeercert(), "response": body}
    tls.close()
    t.update(dns=ms(t1 - t0), tcp=ms(t2 - t1), tls=ms(t3 - t2),
             ttfb=ms(t4 - t3), body=ms(t5 - t4), total=ms(t5 - t0))
    return t, info


# ═══════════════════════════════════════════════════ 2. DNS, by hand
def dns_query(name, qid):
    """A complete DNS question: 12-byte header, the name, type A, class IN."""
    header = struct.pack(">HHHHHH", qid, 0x0100, 1, 0, 0, 0)   # recursion desired
    qname = b"".join(bytes([len(p)]) + p.encode() for p in name.split(".")) + b"\0"
    return header + qname + struct.pack(">HH", 1, 1)


def skip_name(buf, i):
    while True:
        n = buf[i]
        if n == 0:
            return i + 1
        if n & 0xC0 == 0xC0:          # a compression pointer: two bytes, done
            return i + 2
        i += n + 1


def dns_answers(buf):
    qd, an = struct.unpack(">HH", buf[4:8])
    i = 12
    for _ in range(qd):
        i = skip_name(buf, i) + 4
    out = []
    for _ in range(an):
        i = skip_name(buf, i)
        rtype, _cls, ttl, rdlen = struct.unpack(">HHIH", buf[i:i + 10])
        i += 10
        if rtype == 1 and rdlen == 4:
            out.append((socket.inet_ntoa(buf[i:i + 4]), ttl))
        i += rdlen
    return out


def dns_round_trip(qid):
    q = dns_query(HOST, qid)
    with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as u:
        u.settimeout(5)
        t0 = time.perf_counter()
        u.sendto(q, RESOLVER)
        resp, _ = u.recvfrom(512)
        dt = time.perf_counter() - t0
    return ms(dt), len(q), len(resp), dns_answers(resp)


# ═══════════════════════════════════════════════════ 4. connection reuse
def ten_new_connections():
    t0 = time.perf_counter()
    for _ in range(10):
        c = http.client.HTTPSConnection(HOST, timeout=10)
        c.request("GET", "/", headers={"Connection": "close"})
        c.getresponse().read()
        c.close()
    return ms(time.perf_counter() - t0)


def ten_on_one_connection():
    t0 = time.perf_counter()
    c = http.client.HTTPSConnection(HOST, timeout=10)
    for _ in range(10):
        c.request("GET", "/")
        c.getresponse().read()
    c.close()
    return ms(time.perf_counter() - t0)


# ═══════════════════════════════════════════════════ 5. loopback vs internet
class Quiet(http.server.BaseHTTPRequestHandler):
    def do_GET(self):
        body = b"<h1>hello from localhost</h1>"
        self.send_response(200)
        self.send_header("Content-Type", "text/html")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass


def plain_request(host, port):
    # Deliberately NO timeout here, against the advice of experiment 6. On
    # Windows a socket with a timeout waits via the system timer, whose tick is
    # about 15.6 ms -- so a 0.9 ms loopback request was measured at 8.8 ms on
    # average with timeout=10 (range 0.9-26.7). Over the internet the effect
    # was within noise (checked: same phases, same 3x reuse figure either way),
    # but at loopback speeds it swamps the thing being measured.
    t0 = time.perf_counter()
    c = http.client.HTTPConnection(host, port)
    c.request("GET", "/")
    c.getresponse().read()
    c.close()
    return ms(time.perf_counter() - t0)


def connect_ms(host, port):
    """One TCP handshake: the cleanest single round trip Python can time."""
    t0 = time.perf_counter()
    socket.create_connection((host, port)).close()      # blocking, see plain_request
    return ms(time.perf_counter() - t0)


# ═══════════════════════════════════════════════════ 7. binding
def bind_test(bind_addr, lan_ip):
    """Listen on bind_addr, then try to reach it via loopback and via the LAN address."""
    srv = socket.socket()
    srv.bind((bind_addr, 0))
    srv.listen()
    port = srv.getsockname()[1]
    result = {}
    for label, target in (("via 127.0.0.1", "127.0.0.1"), ("via its network address", lan_ip)):
        try:
            socket.create_connection((target, port), timeout=2).close()
            result[label] = "connected"
        except OSError as exc:
            result[label] = f"failed ({type(exc).__name__})"
    srv.close()
    return result


def lan_address():
    """This machine's address on its network. A UDP connect sends nothing."""
    with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as u:
        u.connect(RESOLVER)
        return u.getsockname()[0]


# ═══════════════════════════════════════════════════ 6. timeouts
def connect_to_nowhere(timeout):
    t0 = time.perf_counter()
    try:
        socket.create_connection(("10.255.255.1", 81), timeout=timeout)
        outcome = "connected?!"
    except OSError as exc:
        outcome = type(exc).__name__
    return time.perf_counter() - t0, outcome


if __name__ == "__main__":
    print(f"{RUNS} runs per experiment; times are median (range)\n")

    # ── 1 ──────────────────────────────────────────────────────────────────
    print("=" * 72)
    print(f"1. One HTTPS request to {HOST}, phase by phase")
    print("=" * 72)
    runs, info = [], None
    for _ in range(RUNS):
        t, info = one_request()
        runs.append(t)
    for key, label in (("dns", "DNS lookup (OS cache)"), ("tcp", "TCP connect"),
                       ("tls", "TLS handshake"), ("ttfb", "request -> first byte"),
                       ("body", "rest of the response"), ("total", "TOTAL")):
        print(f"  {label:24} {summary([r[key] for r in runs])}")
    head, _, body = info["response"].partition(b"\r\n\r\n")
    cert = info["cert"]
    subject = dict(x[0] for x in cert["subject"]).get("commonName")
    issuer = dict(x[0] for x in cert["issuer"]).get("organizationName")
    print(f"\n  server address  {info['ip']}   protocol {info['version']}   cipher {info['cipher']}")
    print(f"  certificate     for {subject!r}, issued by {issuer!r}, valid until {cert['notAfter']}")

    print(f"2. DNS by hand: one UDP packet to {RESOLVER[0]}, one back")
    print("=" * 72)
    dns = [dns_round_trip(qid) for qid in range(1, RUNS + 1)]
    print(f"  round trip      {summary([d[0] for d in dns])}")
    print(f"  question        {dns[0][1]} bytes     answer {dns[0][2]} bytes")
    print(f"  answers         {', '.join(f'{ip} (TTL {ttl} s)' for ip, ttl in dns[0][3])}")
    print(f"  the question, as bytes:\n    {dns_query(HOST, 1).hex(' ')}")

    # ── 3 ──────────────────────────────────────────────────────────────────
    print("\n" + "=" * 72)
    print("3. HTTP is text")
    print("=" * 72)
    print(f"  request: {len(REQUEST)} bytes")
    for line in REQUEST.decode().split("\r\n")[:4]:
        print(f"    {line}")
    print(f"  response: {len(info['response']):,} bytes ({len(head) + 4} of headers, {len(body):,} of body)")
    for line in head.decode().split("\r\n"):
        if line.split(":")[0] in ("Content-Type", "Server", "CF-Cache-Status",
                                  "Connection") or line.startswith("HTTP/"):
            print(f"    {line}")

    # ── 4 ──────────────────────────────────────────────────────────────────
    print("\n" + "=" * 72)
    print("4. Ten requests: ten connections vs one kept-alive connection")
    print("=" * 72)
    new = [ten_new_connections() for _ in range(RUNS)]
    one = [ten_on_one_connection() for _ in range(RUNS)]
    print(f"  ten connections       {summary(new)}   -> {st.median(new) / 10:.1f} ms per request")
    print(f"  one connection        {summary(one)}   -> {st.median(one) / 10:.1f} ms per request")
    print(f"  reuse is {st.median(new) / st.median(one):.1f}x faster")

    # ── 5 ──────────────────────────────────────────────────────────────────
    print("\n" + "=" * 72)
    print("5. Distance: one TCP round trip to three places")
    print("=" * 72)
    srv = http.server.ThreadingHTTPServer(("127.0.0.1", 0), Quiet)
    threading.Thread(target=srv.serve_forever, daemon=True).start()
    port = srv.server_address[1]
    plain_request("127.0.0.1", port)                       # warm up once
    targets = (("this laptop (127.0.0.1)", "127.0.0.1", port),
               ("nearest Cloudflare server (1.1.1.1)", RESOLVER[0], 443),
               (f"{HOST}, port 443", HOST, 443))
    print("  light in fibre covers about 100 km of distance per ms of round trip, so a")
    print("  round trip puts an upper bound on how far away the other end can be")
    for label, host, p in targets:
        v = [connect_ms(host, p) for _ in range(RUNS)]
        bound = ("no distance: this is the operating system's own time" if host == "127.0.0.1"
                 else f"within ~{st.median(v) * 100:,.0f} km")
        print(f"  {label:38} {summary(v, fmt='{:.2f}')}   -> {bound}")
    local = [plain_request("127.0.0.1", port) for _ in range(RUNS)]
    srv.shutdown()
    print(f"  a whole plain-HTTP request to the local server: {summary(local, fmt='{:.2f}')}")

    # ── 6 ──────────────────────────────────────────────────────────────────
    print("\n" + "=" * 72)
    print("6. Connecting to an address that never answers")
    print("=" * 72)
    print(f"  socket.getdefaulttimeout() = {socket.getdefaulttimeout()}   (None: wait as long as the OS will)")
    for timeout in (2, None):
        dt, outcome = connect_to_nowhere(timeout)
        print(f"  timeout={str(timeout):5} gave up after {dt:5.1f} s with {outcome}")

    # ── 7 ──────────────────────────────────────────────────────────────────
    print("\n" + "=" * 72)
    print("7. Binding: who is allowed to reach a server")
    print("=" * 72)
    lan = lan_address()
    kind = "a private address" if lan.startswith(("10.", "192.168.", "172.")) else "a public address"
    print(f"  this laptop's network address is {kind} (not printed)")
    for bind_addr in ("127.0.0.1", "0.0.0.0"):
        r = bind_test(bind_addr, lan)
        print(f"  bound to {bind_addr:9}  " + "   ".join(f"{k}: {v}" for k, v in r.items()))
